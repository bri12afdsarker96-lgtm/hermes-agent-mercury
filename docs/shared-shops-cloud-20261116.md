# 企业店铺资产与跨电脑恢复

## 产品约定

- 店铺档案和登录资料属于企业。创建员工与当前服务员工分别记录。
- 企业管理员可以把店铺服务关系转给本租户有效成员。主管和员工的转移请求由服务端返回 403。
- 仅当前服务员工与企业管理员可见、可操作店铺。A 转给 B 后，A 的服务端列表立即排除此店铺，详情和更新请求也拒绝，B 获得访问权限。创建者记录保留。
- 员工移除店铺时，服务器只保存该员工的隐藏偏好，企业资产、登录密文和资产版本继续保留。
- 同账号另一台电脑同步隐藏偏好。正在执行的任务先完成资源退出，再清理本机档案。
- 重新登录只旋转本机浏览器分区。云端资产 ID、店铺 ID 和版本继续保留。核验为相同店铺后更新登录资料。
- 新增店铺在「店铺与客服」中打开内嵌登录页。核验保存的档案供订单截图、小额打款和飞鸽共用。

## 客户端实现

`apps/desktop/electron/shop-browser-cloud.ts` 定义云端契约、响应校验和平台域名限制。

`shop-browser-session.ts` 导出平台 Cookie 逻辑值及 LocalStorage，在新分区导入，再核验店铺身份。企业登录 Cookie 不进入店铺同步。

`shop-browser-profiles.ts` 维护本机分区、云端版本、个人隐藏和执行占用。云端更新使用 CAS。网络失败保留本机资料，并显示真实同步状态。

云端档案的打开和任务启动强制重新查询权限。列表每 10 秒刷新，打开中的页面与执行通道每 15 秒复核权限，命令之间共享最长 15 秒的元数据校验缓存。撤权后关闭旧页面和执行通道，等待通道退出才清理本机分区。现有 TD 线程和工作簿租约按原生命周期退出。

云端不可用时保留本机文件供恢复，已同步档案隐藏并禁止启动。尚未首次上传的旧本机档案继续保持原有本机功能，待服务器完成部署后迁入企业资产。

`src/enterprise-client/shop-service-assignment.tsx` 只向企业管理员呈现转移操作。它读取公开的档案元数据和现有成员列表，使用真实成员 ID 与资产版本提交。

店铺登录详情与上传使用主进程持有的企业会话。通用 renderer 请求桥拒绝登录详情及登录资料上传路径。转移界面只处理元数据。

## 服务端契约

服务端在独立分支 `feature/cloud-shop-profiles-20261116` 实现，沿用企业认证、租户上下文、强制改密、CSRF 和审计。

| 路径 | 用途 |
| --- | --- |
| `GET /api/shop-login-profiles` | 本人可见企业档案及 `hidden_profile_ids` |
| `GET /api/shop-login-profile?profile_id=UUID` | 本人可访问档案的登录资料 |
| `POST /api/shop-login-profiles` | 创建或 CAS 更新同一店铺的登录资料 |
| `POST /api/shop-login-profiles-delete` | 仅隐藏本人的档案 |
| `POST /api/shop-login-profiles-transfer` | 企业管理员转移服务关系 |

转移保留创建者和登录资料，增加资产版本，并在同一事务中解除目标员工的隐藏偏好。其他员工的个人偏好保留。目标无效、跨租户或版本冲突均拒绝。

## 上线与验收范围

服务端使用独立 SQLite 库和 Fernet 密钥，密钥通过 `HERMES_SHOP_LOGIN_PROFILE_KEY` 预置，库路径通过 `HERMES_SHOP_LOGIN_PROFILE_DB` 指定。密钥与数据库共同纳入企业备份，密钥存放于代码仓库以外。

当前生产服务加载的模块包含历史分支之外的能力，部署应基于实际模块进行增量接入。当前批次先完成本地实现和测试，生产部署另行确认。

真实 Electron 本地验收使用合成登录数据，验证平台 Cookie 和 LocalStorage 跨分区恢复、企业 Cookie 排除及进程重启。物理第二台电脑上的真实店铺恢复和平台风控仍需上线后单独验收。

服务器记录 Cookie 的原有效期。恢复后再次检查真实店铺身份，过期或无法核实的登录显示需重新登录。
