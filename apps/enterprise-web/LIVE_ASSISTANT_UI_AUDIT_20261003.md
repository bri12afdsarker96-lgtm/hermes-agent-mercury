## 必须整改的实见问题

### A1 · P1：模型存在感仍明显，与本次产品方向不一致

- 证据：助手第一行仍直接显示“当前模型”、宽下拉框“企业默认 · deepseek-chat”和“企业模型已就绪”。模型控件宽度明显大于主操作按钮，与人设横列占据整条顶栏。
- 影响：仅在管理设置中折叠回答模型，并未弱化使用界面的模型存在感；日常坐席仍先看到模型名称和技术选择。
- 建议：常态仅显示业务人设/回复风格；把模型选择移入低频“更多设置”，采用业务命名，不暴露供应商及模型 ID。管理员仍可在高级设置看到真实参数，不能以 UI 隐藏代替权限控制。
- 验收：已配置默认模型的坐席首屏不出现供应商/模型 ID；管理员仍可经高级入口正确查看和配置，问答请求行为不变。

### A2 · P2：模型下拉有三个近似重复选项

- 证据：同一真实页面列表同时有“企业默认 · deepseek-chat”“deepseek · deepseek-chat”“deepseek · deepseek-chat（企业默认）”。
- 影响：用户无法理解选它们是否有业务差别。
- 建议：基于真实配置标识判断是否重复；默认项仅保留一个清晰入口，确需保留的其他配置用管理员给出的业务名称区分，不依据文字相同直接删除配置。
- 验收：每个可选项表达明确且唯一的用户选择；重复引用同一配置不生成重复菜单项。

### A3 · P2：空对话占高过多，输入区与主按钮分离

- 证据：空对话仅一行介绍，正文大块空白；输入区在底部，整个空页面仍需要额外滚动 40px 才完整露出卡片底部。
- 影响：空白不承载工作内容，首次进入注意力停留在介绍而非输入；在更矮屏幕上主操作可达性值得重点验证。
- 建议：空态压缩为短提示，输入区保持在可见底部；固定顶栏、正文和输入区的高度预算，避免空对话就产生外层溢出。长回答允许单一明确的内容滚动区。
- 验收：1706×960 与常用 1366×768 下空对话无需外层滚动即可看到输入、附件和发送；长回答不遮挡输入。

### A4 · P2：提示重复且技术过程文字仍多

- 证据：左栏“结合企业知识库进行问答、分析与工作协作。”；正文“直接输入问题即可开始，也可以让 AI 摘要、改写或整理待办。对话仅保留在当前登录会话中。”；历史标题旁又写“当前登录会话 · 刷新保持”；附件旁写“选择后在本机读取，提交后交由企业 AI 处理。”。
- 建议：左栏介绍可去除；正文空态只保留“输入问题开始对话”；会话保留规则属于真实数据保留限制，不应全部隐藏，集中到历史区一个短说明/帮助提示；文件处理实现流程移入帮助，不常驻。
- 验收：常规界面同一概念只解释一次；退出后历史是否保留仍有准确提示，不能为简洁误导用户。

### A5 · P2：文件能力限制有文字，没有就近动作

- 证据：下方仅文字“DOC、DOCX、PDF 请先上传企业知识库。”，主按钮“选择本地文本文件”；DOM 有两个同名按钮，截图只有一个视觉按钮。
- 建议：把格式限制缩成“文本文件”辅助提示；在不支持文档的场景提供明确“去知识库上传”链接并保留当前草稿。检查同名双按钮是否隐藏 file input 与可见按钮同时被辅助技术识别，避免键盘重复停留。
- 验收：用户能从此处找到文档入口；辅助技术只暴露一个实际文件选择操作或能区分两者用途。当前仅能确定语义树重复，未完成键盘复测。

### A6 · P2：“定时提醒”却首先展开全企业任务收件箱

- 证据：点击助手里的“定时提醒”，弹层标题“提醒中心”，默认选“待处理任务”，出现 38 条全企业任务，不是新建提醒表单。
- 影响：用户在对话中点击定时提醒，预期安排时间，实际先遇到团队、人员、状态筛选和大量应收款任务。
- 建议：若按钮保留“定时提醒”，默认落在“新建提醒”；若目的是任务管理，应改为“提醒中心”。保留侧栏入口管理所有任务，避免聊天中再复制完整管理面板成为第二个主工作台。
- 验收：按钮名称与点击后第一步一致；既有待办管理仍可进入，无需额外绕行。

### A7 · P2：提醒弹层嵌套滚动，首屏有效任务区域过小

- 证据：实际有页面主滚动区、dialog 滚动区（788px 高/982px 内容）、task-list 内滚动区（499px 高/4981px 内容）。首屏筛选区占据大量高度，任务卡仅露约 2.5 条，任务列表下部又被外层 dialog 裁切。
- 建议：弹层只保留一层纵向滚动或升级独立页面；压缩重复标题与筛选空隙，团队→人员→搜索→状态顺序一致，固定必要工具栏，任务列表使用紧凑行而非每条大卡片。
- 验收：38 条数据逐屏滚动无卡片内容被另一滚动容器遮挡；滚动不会意外移动背景；最下条任务和关闭操作均可达。

### A8 · P2：提醒任务卡重复状态、币种及内部 ID

- 证据：每卡同时显示“应收款跟进”“逾期风险”“逾期未处理”；应收金额反复显示“666.00 CNY”等；历史成员显示括号内 p_… 标识。
- 建议：保留业务类型+一个真实状态/逾期时长，不重复风险与同义状态；人民币统一“¥”；历史成员优先用可识别的保存名称，只有无法找回姓名时展示“历史成员”，内部 ID 放可折叠审计详情。
- 验收：普通列表无 CNY 和数据库式成员 ID；审计详情仍能追溯唯一主体。不能把任务逾期与款项逾期混为同一业务概念。

### A9 · P3：全局非操作性信息占据固定空间

- 证据：顶栏禁用“客户端安装包准备中”；顶栏重复 Hermes 品牌、用户/角色，底部再次显示 Hermes-企业助手、身份企业管理员、“安全连接 · 服务端权限”。
- 建议：未就绪客户端下载移入帮助/关于；角色保留顶栏一处；连接异常才突出提示，常态连接状态简化。底栏避免解释实现权限逻辑。
- 验收：不降低断线提示可见性；用户始终可确认当前企业与身份，但不出现多处相同身份信息。

## 跨入口补充（真实 DOM，尚需对应负责 agent 截图复核）

进入助手前实际读取的运营总览尾部仍包含“企业任务执行”“呈现服务端任务状态、停滞标记和人工认领事实。生命周期命令仍须由 Hermes_AI 校验权限与状态机。”“选择一条服务端任务以查看其授权投影。”“认领记录来自所选任务的服务端 assignment 账本。”以及同块“已连接”与“等待企业服务连接”。这些是实现/内部诊断语言，而非普通企业业务操作语言。建议由总览负责人截图核实后，移入诊断权限入口或改成准确业务状态；不能因为空列表就把连接正常写成等待连接。

## 保留的有效设计

- 输入框边框和主操作按钮对比已可见，无需因风格喜好推倒重做。
- 对话记录使用独立侧栏，菜单把删除与普通动作分开，删除颜色有区别。
- 已存在禁用空白提交，避免用户无内容误发。
- 团队、人员、状态均是可选择控件，比自由文本筛选更清晰。
