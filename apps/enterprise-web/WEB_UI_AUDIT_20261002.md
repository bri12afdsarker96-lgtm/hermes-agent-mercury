# 网页版 UI 与功能入口映射审查

日期：2026-10-02。审查角色：Agency Agents 的 UI Designer + UX Architect。

## 范围与证据边界

本次只读检查网页版入口、共享企业组件及样式，未修改业务代码、客户端、权限或金额计算规则。仅新增此报告。审查期间主任务仍在修改收款概览、金额筛选和单任务详情，因此本报告中的“本次覆盖”指已纳入主任务，**不等于已经测试通过或上线**。

证据来自源码及用户提供的历史截图。没有操作真实业务数据，没有使用当前登录会话提交表单，也没有对当前生产网页重新做逐页截图或屏幕阅读器验收。代码能够确认的样式/映射问题与需浏览器确认的视觉表现分开表述；不以历史截图断言新版仍缺失功能。

源码根目录：`D:/GitHub/同步/hermes-agent-mercury/.worktrees/enterprise-client`。下文 `shared/` 表示 `apps/desktop/src/enterprise-client/`，`ui/` 表示 `apps/desktop/src/components/ui/`，`web/` 表示 `apps/enterprise-web/src/`。行号为审查时定位，主任务继续编辑后可能移动，应同时按控件/函数名定位。

## 结论

问题不是“应收款的一个输入框太暗”，而是三套控件混用：带样式的 `Input`、空值时主动淡出的 `SearchField`、只有局部布局样式的原生 `input/select/textarea`。只修改 `Input` 不能覆盖提醒、分组和知识审核中的裸控件。

本次收款金额映射的代码方向正确：概览跳入清空旧的基础筛选和分页；同页金额选择清除旧日期；币种分组、明细币种标识已存在。发布验收应重点证明这些路径，而不能只看金额卡是否出现。

## 优先整改清单

P1：影响关键任务发现或操作判断，优先修正。P2：一致性、可理解性或效率问题。没有凭静态检查推定的数据损坏或越权问题。

### UI-01 · P1 · 搜索默认淡出，和可输入区域难以区分

- 页面/控件：逾期未处理搜索；旧应收款搜索；正在开发的新网页收款查询。
- 证据：`ui/search-field.tsx:63` 使用透明下边框；`:65` 空值时 `opacity-30`；`:77` 透明输入背景。`shared/followup-filters.tsx:33`、`shared/overdue-page.tsx:22`、`web/receivables-overview.tsx:67` 沿用默认样式。提醒收件箱本身不是这个组件的消费者。
- 问题：最需要被发现的空搜索框反而最淡；光标聚焦后才明显不能解决首次发现。这里只确认存在 30% 样式，未测量生产页实际对比度。
- 建议：网页企业范围提供明确的搜索外观/可见标签；稳定宽度、常态不透明、可辨识搜索图标、清除动作与查询按钮区分。不要全局修改桌面 `SearchField` 使客户端变化。
- 验收：空值、输入值、聚焦、禁用、窄窗口均可识别；键盘 Tab 可定位；输入清空后仍明显。新报表查询字段不会被误认为新建业务对象。
- 状态：主任务已接受新报表搜索修正；逾期页共性修正需单独确认范围。

### UI-02 · P1 · 新建应收款与查询已有记录缺少清晰分区

- 证据：`shared/receivables-page.tsx:214` 插入统计区，`:218` 后直接出现创建表单；字段循环未提供新建标题、业务对象示例或必填标识；`validReceivable` 在 `:37` 要求对象、金额和预计日期。
- 问题：页面上下存在同名“业务对象/群名称”，但一个用于筛选，一个用于新增。只有“新建”按钮无法让用户先于输入辨认用途。
- 建议：明确“查询已有应收款”和“新建应收款”两个区域；新建区可折叠但入口明显；关键字段标必填，金额显示单位与格式提示；按钮文案用“创建应收款”。不得改变现有金额校验、幂等提交或权限。
- 验收：用户在不点击任何控件时能辨认两种输入的作用；查询绝不创建记录；取消/折叠草稿不误触提交；新建成功反馈独立于查询空结果。
- 状态：本次主任务已接受。

### UI-03 · P1 · 提醒中心原生表单没有完整常态控件样式

- 验收：空的提醒事项也能看出输入范围；日期时间在不聚焦时可辨；默认班次与具体时间语义不混淆；改期控件相同标准。

## 本次发布建议验收路径

1. 应收款先设搜索、负责人、历史、非第 1 页，再返回总览点“当日待收款”：基础筛选与旧分页清空，明细与概览金额同币种同日期；总览已有跳转代码正确重置，应以测试证明。
2. 在应收页面保留业务搜索，依次点“未收总额 → 关闭/取消未收 → 某日金额 → 已确认收款”：只替换一份列表；旧单项日期/类别条件不残留，基础搜索仍生效。
3. 改期、部分收款或关闭一条测试任务后：概览金额、应收卡片、每日金额和详情均重新读取服务端事实；历史未收不伪装已收。
4. 三种入口分别打开同一任务：应收、逾期、提醒中心，详情内容和允许操作一致；一次只出现该任务，不显示其他任务或新建表单。
