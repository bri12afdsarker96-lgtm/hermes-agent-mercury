## P1：优先整改/验证

### B01 跨入口沿用旧滚动位置，用户进入即丢失标题和筛选

- 证据：在运营总览底部切换左侧“逾期未处理”后，首个截图直接落在任务列表中段，标题、筛选区均在上方；向上滚动才能找回。
- 影响：看不到当前筛选范围，易误认为页面缺项，尤其在管理员操作前不清楚对象范围。
- 建议：切换新的主入口重置主滚动容器至顶部；只在“详情返回列表”时恢复原列表位置。不要所有导航一律清零。
- 验收：任一长页底部切换四个业务入口，新入口标题/筛选可见；打开某行详情再返回，原行仍可定位。

### B02 应收款历史内表滚动位置不稳定，妨碍历史查阅

- 证据：正常 PageDown 后只读 DOM 测得内表 `scrollTop=1154.67`，下一次截图又显示第一行，随后测得 `scrollTop=0`；多次合法滚动仍回到首段。最后一次对第 16 个“查看与处理”按钮使用 PageUp 后截图仍为第 1–8 行。当前跟进表曾能完成两页滚动。
- 限定：工具单次截图有约 21 秒等待，可能跨越后台刷新周期；**尚未证明是定时刷新或某个具体重渲染原因**。不是已确认的 API 数据错误。
- 影响：用户难以读取或操作表格中后段，当前审查也无法可靠证明历史全量覆盖。
- 建议：检查刷新是否更换表格节点/重置列表状态；保留筛选、页码、内表滚动与当前焦点，刷新仅更新记录。需要独立人工鼠标复现确认。
- 验收：历史第 1 页滚到中/底部等待至少两个实际刷新周期，位置不跳；第 2 页也稳定；详情关闭恢复原行。

### B03 管理员个人提醒权限说明与实际范围矛盾

- 证据：逾期入口说明仍有“坐席私人提醒不在此范围内”，但当前管理员列表中实际出现 3 条个人提醒；用户已明确管理员可查看并删除本企业所有成员定时提醒。
- 影响：管理员误解权限；后续维护可能把合法权限当成泄漏而错误收紧。
- 建议：按角色生成短说明或不在首屏赘述；管理员显示“本企业待处理事项”，权限边界由服务端强制。不要为匹配旧文案撤回已授权能力。
- 验收：管理员看本企业全部授权提醒；主管/坐席保持各自边界；三个角色文案和实际列表一致，跨租户不可见。

## P2：业务映射与可操作性

### B04 任务列表混合类型，列名却使用单一业务含义

- 证据：逾期表中列名为“人员筛选”“预计到账日期”，同表包含个人提醒。
- 影响：表格数据与筛选控件概念混淆；个人提醒日期被错误表达为到账。
- 建议：统一为“负责人”“到期/提醒时间”，用类型标记区分应收款与个人提醒；应收款详细的原约定日留到对应详情。
- 验收：两类任务同表均能准确理解负责人、任务类型与截止时间，不将个人提醒描述为收款。

### B05 处理历史是粘连文本，不是可检索审计记录

- 证据：26 条均以“催收所属成员：张峰历史已结束（未记录处理方式）2026/9/30 15:29:48”式单行连续文字呈现，缺少列、标签、搜索、来源/人员过滤与详情。
- 影响：无法快速区分自己的、坐席的、管理员删除的或其他结束方式，历史存在但难以使用。
- 建议：结构化为任务、来源、负责人、处理结果、处理人、时间；加关键词、团队/人员、结果筛选。旧数据保留“已结束·旧记录/方式未记录”，不能冒充“已完成”。
- 验收：按本人/成员、管理员删除/完成/取消等查找；新删除记录能看到操作者与时间；旧数据不伪造原因；时间倒序保持。

### B06 人名缺失时大量暴露内部主体 ID

- 证据：逾期及应收款记录出现很长的历史成员 `p_…`；任务操作历史也直接展示 `p_nta…` 类 ID。应收款第 2 页长 ID 撑宽负责人列。
- 影响：看不出是谁，破坏表格尺寸；也暴露无助操作的技术标识。
- 建议：优先显示保存的历史姓名，缺失时使用“已离职成员/历史成员”；完整 ID 仅详情复制或提示中提供，勿把不同历史成员错误合并。
- 验收：活跃/离职/已删除负责人均可识别且列宽稳定，审计身份仍可追溯。

### B07 收款卡构成关系命名错误，金额映射需清晰

- 证据：“未收构成”后并列跟进中未收 42,590.71、关闭取消未收 30,121.00、应收总额 193,501.79；“应收总额”显然不是未收的构成分量。未收总额快照为 72,711.71，累计已确认 120,790.08。
- 影响：用户可能把总额当成未收子项；相同数值的“跟进中未收”和“逾期未收”也容易误认为重复业务。
- 建议：独立呈现“未收构成”与“应收总额”。跟进中未收是状态范围，逾期未收是日期范围，不能因为今日数值相同就直接删掉语义；可把非核心项收起为可展开构成。
- 验收：所有金额点击后明细筛选及金额合计可核对；未来未到期任务不会进入逾期；关闭项按最新批准口径归属。

### B08 用户最新“关闭/取消未收冲销”要求需独立账务动作

- 证据：本轮现场口径明确“未收总额包含关闭/取消未收；关闭不等于收款”。主线程转告用户新选择：希望关闭/取消未收时冲销余额，另做明确确认。
- 性质：**新增业务口径，不是本报告证明的旧计算 bug**。审查未操作任何余额。
- 建议：状态结束、停止提醒、冲销余额、已收款四者分开表达；新确认应列本次冲销、冲销后余额及不代表到账，并保留操作者/原因/时间/原始应收与收款流水。历史旧关闭记录不可静默批量清零。
- 验收：部分收款后仅剩余余额可冲销；汇总与明细一致，重复提交不重复冲销；历史原始事实仍可追溯，已收款不被冲销伪造。

### B09 提醒收件箱的筛选维度混排、卡片重复信息过多

- 证据：全部/应收款/个人提醒/逾期未处理/待跟进混在同一组标签；38 个大红卡片连续约七屏，每张再重复类型、逾期风险、逾期未处理，操作按钮很小。
- 影响：无法组合“个人提醒且逾期”等条件；全红背景让重要程度失去区分，管理员处理效率低。
- 建议：分离类型与状态筛选，增加结果数；大批任务用紧凑列表，保留对象、负责人、截止时间、金额和清晰主操作。逾期用一处明确标记即可。
- 验收：类型与状态可组合，筛选不意外清空另一维度；38 项可快速浏览，键盘可到达详情；无状态重复堆叠。

### B10 应收款页面首屏被筛选及零值日期卡挤占

- 证据：金额卡后有两个半屏宽团队/人员控件、搜索/状态行、展开日期条件、7 张连续为 0.00 CNY/0 项的每日卡，再到“当前跟进/历史”和任务明细。
- 影响：用户点击金额后仍需下滑较长距离才能看到所选任务；重要列表被非当前操作信息压低。
- 建议：保留金额 → 团队 → 人员 → 对应任务主顺序；把每日计划做紧凑横向日期条/可收起区；点击金额让明细标题与前几行立即进入视野，别自动展示其他分类。
- 验收：常见桌面尺寸点击任一金额后可立即辨认选中范围和首条任务；7 天全零时不占整块大区域；日期计划与台账筛选有清楚而简短的范围提示。

### B11 业务对象汇总没有进一步定位任务的入口

- 证据：当前明细汇总为 27 行静态金额表；未见行或金额按钮，且标题叫“当前明细”，实际包含全部 35 项而非当前 10 行分页。
- 影响：看到某群/对象的金额后仍需回到顶部手动搜索，范围也不明确。
- 建议：称“当前筛选汇总”，对象/金额提供下钻到对应任务；继承权限、团队、人员与当前金额分类，不能跳回全部。
- 验收：点击汇总某对象只出现该对象同范围任务，合计相符；返回恢复原筛选/页码。

## P2：视觉、文字与信息层级

### B12 页面底部技术执行模块冗长并存在矛盾空态

- 证据：运营总览下方“企业任务执行”显示“生命周期命令仍须由 Hermes_AI 校验权限与状态机”“授权投影”“服务端 assignment 账本”；同区既有“已连接”又有“等待企业服务连接”。当时没有已选任务。
- 影响：暴露实现逻辑，普通用户无法操作；把未选择误报为未连接会引起故障误判。
- 建议：无业务用途时收起/从总览隐藏，不删除模块代码；若保留，采用“选择任务查看详情”空态，连接状态仅由真实连接决定。内部账本/状态机说明移到受限诊断。
- 验收：未选任务与未连接为不同空态，首屏/底部均无实现名词；仍可通过合法管理入口查看必要事实。

### B13 默认人民币格式未统一，金额难比较

- 证据：总览及金额卡用 ¥，每日卡、应收款行、详情和对象汇总仍出现 CNY；金额多为左对齐且缺千位分隔，对象汇总还单独占一列“币种 CNY”。
- 影响：重复单位浪费宽度，数额位数难以纵向比较。
- 建议：全站统一人民币符号/列头单位、两位小数和千位分隔；表内数字右对齐并用等宽数字；默认单币种不保留重复币种列。保留真实多币种数据处理边界，不做盲目转换。
- 验收：金额卡、日期卡、列表、详情、汇总格式一致；大金额不挤压负责人或操作列。

### B14 通知历史泄露状态枚举，触发/送达解释重复

- 证据：触发历史状态直接为 `cancelled`、`stale`；两个展开区域重复“触发记录与通知送达是两个阶段；这里不将已触发显示为已送达”。触发20行但未见记录范围/分页说明；投递空表仍展示全部技术列。
- 影响：用户无法判断状态，长解释和空表占空间；不能确认是否看到了全部历史。
- 建议：准确映射取消/已失效等中文状态，保留触发与送达事实差异但用列名/一处帮助解释。显示“最近 N 条”或分页；空表改明确空态。错误类别等诊断折叠在失败记录详情。
- 验收：无原始英文枚举；成功/失败/取消/失效/仅触发不能混淆；记录范围可见且可查更早记录（如产品支持）。

### B15 通知设置没有独立视觉分组

- 证据：通知开关、音量、试听与“首次提醒后…30分钟…客户端需保持运行…”在一个长水平行，且位于两历史折叠之后。
- 影响：设置与日志层级倒置，控件难发现；网页场景提客户端也易误解。
- 建议：先独立“提醒通知”设置卡：声音开关、音量、试听各有清楚标签；运行条件按网页/客户端实际能力生成一行说明，补提醒规则放短提示。
- 验收：不展开历史就能找到声音设置；窄屏不挤成一行；文案符合当前载体，不误称关闭网页后还能播放本地声音。

### B16 单任务详情的按钮与折叠标题不匹配

- 证据：刷新当前任务占满近整行；管理员删除是很小的中性按钮；“备注与负责人转交”展开后管理员视角只有转交，没有备注输入；空收款流水仍占完整表格。
- 影响：低频刷新抢空间，危险操作不易识别；标题承诺不存在的能力。
- 建议：刷新放标题侧小按钮，删除为明确危险样式且保留确认；按角色命名“负责人转交”；空流水用一行空态。保留不代表银行对账等必要风险信息，勿为减少文案删去财务含义。
- 验收：管理员清楚知道可做/不可做事项；危险操作先有对象和后果确认；详情只显示当前选中任务。

### B17 表格滚动、列宽与人员筛选次序不统一

- 证据：逾期全外层长表无固定表头，应收款是固定624像素内表加外层滚动；当前预计日与原约定日多数重复；团队与人员有时被搜索分开；历史原始 ID 撑列。
- 影响：跨页操作心智不一致，找条件/找列名都费力。
- 建议：统一列表壳，按页面高度安排单一主滚动或清晰内表；筛选紧邻“团队→人员→业务对象→状态”，原约定日有变化时突出差异或移到详情，但不能删掉逾期口径依据。
- 验收：表头和关键操作在长列表仍易见；切换页码列宽不跳；选团队后人员仅显示其范围（当前审查未独立验证此联动，须测试）。
