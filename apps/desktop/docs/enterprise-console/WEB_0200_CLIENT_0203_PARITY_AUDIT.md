# 网页 0.20.0 与客户端 0.20.3 功能反查

核查日期：2026-09-10。以用户确认的客户端截图版本 0.20.3 为准。
本记录是代码与部署产物核查，未执行真实账户改密、退出登录或应收款写入，也不表示已完成修复或发布。

## 已确认的遗漏原因

线上首页 `https://ppbb096.site/` 实际返回的发布标识为 0.20.0，但运行内容不只有 React 主构建。
通过 HTTPS 读取首页，并通过 SSH 对照服务器
`/opt/hermes/releases/enterprise-web-v0.20.0-deffbab/enterprise_web/index.html`，确认加载：

| 线上额外入口 | 实际职责 |
| --- | --- |
| `enterprise-account-controls-20260909.js/css?v=account-controls-r2` | 账户安全卡、日常修改密码、退出登录；隐藏总览快捷工作大卡并调整数据卡间距 |
| `enterprise-assistant-boundary-20260909.js/css?v=assistant-boundary-r3` | 检索与摘要折叠块、主回答复制按钮、补充回复卡片及布局 |
| `followup-board-20260907.js?v=receivable-inbox-sync-r12` 及对应 CSS | 应收款全局入口、新建应收款、本人创建的跟进列表、创建后通知提醒中心刷新 |
| `enterprise-reminder-expanded-20260909.css?v=reminder-expanded-r1` | 提醒中心宽度、高度和内部滚动规则 |
| `index-JPKtuf6b-reminder-action-fix-20260909.js` | 线上经过追加修订的主构建；不是本地网页入口中同名的原始主构建 |

客户端 `dist/index.html` 没有以上追加入口；`src/enterprise-client` 中也没有导入这些文件。
本地 `apps/enterprise-web/src/main.tsx` 虽然与桌面端复用 `EnterpriseClientApp`，但不等于已经包含线上 HTML 追加的功能。
仅比较共享源码、接口名称或页面数量，会漏掉这层运行时功能。

## 确认结果

| 功能/行为 | 客户端现状 | 结论及证据 |
| --- | --- | --- |
| 日常修改密码 | `app.tsx` 仅在 `passwordChangeRequired` 为真时挂载改密页面；正常工作台与账户区无主动入口 | 缺失。首次登录改密不能算作日常改密已实现 |
| 首次登录强制改密 | 已有页面及 `/api/password-change` 调用 | 已有代码路径；不需要重复建设 |
| 账户安全区与退出登录 | Shell 账户区仅展示身份；工作台没有账户安全卡或退出按钮 | 缺失用户可达入口。底层 `disconnect` 不等于已有退出流程 |
| 应收款全局入口 | 导航与 Shell 未挂载应收款创建面板 | 缺失 |
| 新建应收款并建立提醒 | 未找到 `POST /api/business-followups` 的客户端创建调用 | 缺失。网页提交对象/群、团队、金额、应收日期、预计到账日及幂等键 |
| 我创建的应收款与刷新 | 只读取提醒投影及某条跟进详情，没有网页的 `GET /api/business-followups?scope=personal` 列表入口 | 不完整。提醒待办不能替代原始应收款记录列表 |
| 已有应收款查看、改期、处理结果 | `assistant-reminders.tsx` 已调用详情接口及 `/api/business-followup-action` | 部分已实现，不能据此宣称应收款完整可用 |
| 创建应收款后立即刷新提醒中心 | 网页发布并监听 `hermes:followup-changed`；客户端只有定时/焦点/网络刷新 | 缺少创建流程及其即时联动 |
| 总览快捷工作与卡片间距 | 客户端直接渲染快捷工作大卡；网页账户脚本将该卡隐藏，并追加数据看板间距样式 | 确定的布局差异，不能归因于分辨率或用户版本错误 |
| 提醒中心完整页面布局 | 0.20.3 已有全宽样式，但采用 `max-height:none; overflow:visible`，网页追加样式使用受限高度与内部滚动 | 属于实现差异，不能笼统宣称客户端尚无全宽样式；需要同窗口尺寸验收 |
| 主回答、补充回复与复制位置 | 客户端展示主回答后渲染所有返回选项，最后才放主回答操作；网页追加脚本将复制按钮移入主回答卡 | 确定的展示差异；主回答与 `current_reply` 可能重复 |
| 备用回复缺失 | 客户端解析器已识别 `alternative_reply` | 不能直接认定字段漏接；须检查同一次响应的选项内容。不能在客户端编造备用话术 |

## 测试为何没有暴露这些遗漏

- `assistant-reminders.test.tsx` 的应收款测试直接提供一条现成任务，验证显示和“已收款”动作；没有从新建入口开始。
- `login-page.test.tsx` 验证首次登录改密；未覆盖正常登录后主动修改密码。
- `assistant-page.test.tsx` 验证结构化返回字段的展示；没有与线上追加脚本共同构成的完整界面比较。
- 因而这些测试即使通过，也不能作为全功能对齐证明。

## 下一次完整对齐的必验收项

1. 以线上实际加载的 HTML、JS/CSS 及服务端接口为清单，逐个对照客户端可达入口，而非只对照本地共享源码。
2. 正常登录后能主动修改密码；验证当前密码、新密码确认、错误反馈、会话令牌轮换，并验证“记住密码”不会继续保留旧密码。
3. 从账户入口退出，确认业务页面和当前会话正确清理；明确对未保存草稿的处理，并验证重新登录后的身份隔离。
4. 从客户端入口创建一笔应收款，读取本人列表，在提醒中心查看同一条记录，完成改期/收款/关闭后验证服务端回写与界面刷新。
5. 不通过普通“企业任务执行”面板替代应收款面板，两者接口与业务流程不同。
6. 同一窗口尺寸对比总览、提醒中心和问答布局；同一账号、模型、人设、上下文和知识状态对比问答契约，避免用不同请求的文案相似度判断功能对齐。
7. 以实际打包产物验证上述入口和流程，完成后再更新在线发布描述；未验证项目保持待验收，不写成全部完成。

账户与应收款所需的服务端接口已经存在；这些已确认入口遗漏主要需要客户端实现。
网页使用 Cookie 的 `/api/browser-password-change` 与 `/api/browser-logout`，桌面端使用主进程会话，不能直接复制网页认证代码替代桌面认证流程。

本清单覆盖本次已检查的线上追加功能及相关路径，不代表所有业务模块已经完成全量交互验收。
