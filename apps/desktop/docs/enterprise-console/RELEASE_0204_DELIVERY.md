# 0.20.4 客户端缺口迭代

日期：2026-09-10。基线为用户截图确认的客户端 0.20.3，以及线上网页 0.20.0 实际加载的追加脚本，而不是只比较版本号。

## 本轮实现

| 缺口 | 入口与交付 |
| --- | --- |
| 主动修改密码、退出 | 右上角“账户安全”；当前密码、新密码确认；主进程消费轮换令牌，普通改密清除旧的记住密码；退出释放桌面会话及本机记住的登录信息 |
| 应收款创建、本人列表 | 左侧“应收款跟进”；按真实权限展示，创建、刷新、查看与处理；使用既有提醒中心的收款、改期、取消、关闭流程 |
| 重复创建与提醒联动 | 超时重试复用原始请求和幂等编号；明确拒绝允许改正草稿；创建和结果处理触发身份范围内刷新 |
| 问答呈现 | 主回复和重复的 current_reply 只显示一次；保留不同的跟进和备选内容；检索/摘要可折叠，复制操作放回各自卡片；不编造服务端未返回的备选答案 |
| 间距 | 总览快捷大卡收纳至底部；数据看板使用线上追加样式的 32/28px 间距；小屏保持 24/20px；提醒页受限高度和内部滚动 |
| 历史上传、重新切分 | 企业知识中打开历史上传继续处理 staged/edited 批次；重新切分校验字符数和重叠范围，拒绝覆盖未保存的分块编辑 |
| 提醒与投递记录 | 提醒中心展开“提醒触发历史”“通知投递记录”；权限控制、只读、按需读取，不把触发当成送达 |
| 企微本人状态 | 工具集内主管/坐席本人值守，坐席本人自动答复；服务端确认后更新，不乐观显示成功 |

新增表单纳入既有在线更新保存保护。安装包继续包含 OpenVPN Connect，引导安装和更新源保持原路径。

- 本地服务端应收款与知识上传契约测试：67 项通过、1 项跳过。使用临时数据库，不触碰生产业务数据。
- 实际 `release/0.20.4/win-unpacked` 包执行验收：版本、入口、新建/查看应收款、问答去重及备选、改密、历史上传/重新切分、退出；1280×900 与 1920×1080 截图。数据采用隔离的 IPC 契约夹具，这不是生产账号业务写入、实际模型质量或企微送达验收。

- 安装器未配置 Authenticode 签名，Windows 可能显示未知发布者提示；哈希校验不是数字签名，不应将本包称为已签名版本。
- 工作树包含已有未提交修改，未擅自提交或清理；构建戳如实标记 dirty，具体产物以哈希为准。

## 尚未交付，不冒充全接口覆盖

- 细粒度权限委派、租户高级运行策略仍未提供完整管理界面。
- 业务任务 create/retry/close/escalate 的执行载体是 device/broadcast/workflow，并非个人提醒；其中升级又关联已要求隐藏的接管流程，本轮没有直接开放。
- 设备、引擎调度、历史记忆、DEV 能力策略、事件流增强等沿用审计分类，未变成普通坐席菜单。
- 人工接管、多客户接待、录音与学习反馈保持既定隐藏/冻结状态。
- 本轮不修改服务器模型、人设或生成规则。对照回答文案时仍需同账号、同模型、人设和上下文；客户端不得伪造替代答案来掩盖服务端返回差异。
